# Design View Constraints Reference: core-design

**Skill**: core-design
**Usage**: 本文档由 SKILL.md Phase 2 通过 GATE 加载，Agent 在生成 delta_design.md 时必须按本文档要求产出 PlantUML 视图。

---

## 1. 必须视图（任何需求不可省略）

以下视图在任何设计文档中必须产出，无论需求复杂度如何。

| 章节 | 视图类型 | PlantUML 图类型 | 质量要求 |
|------|---------|----------------|----------|
| 二、系统架构 2.1 整体架构 | 架构图 | `component diagram` | 必须体现层次边界和层间调用规则；禁止三行空壳图 |
| 二、系统架构 2.2 模块划分 | 模块依赖图 | `component diagram` | 必须体现模块名、依赖方向（箭头=依赖方向）；禁止出现环 |
| 三、详细设计 3.1 核心模块设计 | 类/接口关系图 | `class diagram` | 必须体现类名、关键属性、关键方法、类间关系（继承/组合/依赖/实现） |
| 六、核心流程设计 6.1 | 时序图 | `sequence diagram` | 必须覆盖 happy path + 至少一条异常路径（alt/else）；禁止只有 happy path |

**空壳图判定规则**：
- `@startuml A --> B @enduml` 这种不超过 5 行的图视为空壳，必须补充实际元素
- 类图中类无属性且无方法视为空壳
- 时序图无分支（alt/else/opt）且消息数 <= 3 条视为空壳

## 2. 条件视图（满足触发条件时必须产出）

### 2.1 逻辑视图（Logical View）

| 视图 | 触发条件 | PlantUML | 章节 | 质量要求 |
|------|---------|----------|------|----------|
| 用例图 | 新增面向用户的业务功能 | `usecase diagram` | 一、设计概述 1.1 | 必须体现 Actor + Use Case + include/extend 关系 |
| 实体关系图 | >= 2 个数据实体且有关联关系 | `class diagram`（ER 风格） | 三、详细设计 3.3 | 必须体现实体、属性、1:1/1:N/N:M 关系 |

### 2.2 进程视图（Process View）

| 视图 | 触发条件 | PlantUML | 章节 | 质量要求 |
|------|---------|----------|------|----------|
| 状态图 | 涉及状态机/生命周期管理（如订单状态、任务状态） | `state diagram` | 三、详细设计 3.1 | 必须体现初始态、终态、转移条件、动作 |
| 活动图 | 流程含分支/并行/条件判断（>3个分支点） | `activity diagram` | 四、算法设计 或 六、核心流程 | 必须体现分支（decision）、并行（fork/join）；涉及多角色时使用泳道 |

### 2.3 物理视图（Physical View）

| 视图 | 触发条件 | PlantUML | 章节 | 质量要求 |
|------|---------|----------|------|----------|
| 部署图 | 涉及多节点/多进程/多服务部署 | `deployment diagram` | 十三、部署设计 13.1 | 必须体现节点（服务器/容器/进程）、制品（artifact）、通信协议 |

## 3. 视图质量约束

### 3.1 元素一致性
- 类图中的类名必须与 3.1"关键类/接口"表格中的名称一致
- 模块依赖图中的模块名必须与 2.2"模块划分"表格一致
- 时序图中的参与者必须在 2.2"模块划分"或 3.2"接口清单"中找到定义
- 实体关系图中的实体名必须与 3.3"数据归属操作表"中的表名一致

### 3.2 禁止占位骨架图
- 任何 PlantUML 图的实际内容行数不得少于 8 行（不含 @startuml/@enduml）
- 图中所有元素必须使用实际名称（类名、方法名、消息名），禁止使用 `<XXX>` 占位

### 3.3 异常路径覆盖
- 时序图必须包含 `alt`/`else` 或 `opt` 分支展示至少一条失败场景
- 每个外部依赖调用在时序图中必须有超时/失败的 alt 分支

### 3.4 跨图引用一致性
- 架构图（2.1）中标注的模块间调用关系，必须与对应时序图（6.1）中的消息流一致
- 类图（3.1）中的类间依赖关系，必须与模块依赖图（2.2）中的模块依赖方向一致
- 状态图中的状态转移，必须与核心流程时序图中的步骤对应

### 3.5 图与文档交叉引用
- 每个 PlantUML 图前必须有文字说明该图的关注点和阅读指引
- 图中关键元素必须在后文中有详细描述（不能只出现在图中而文字不提）

## 4. PlantUML 图类型速查

| 图类型 | 关键字 | 适用章节 |
|--------|--------|----------|
| component | `@startuml [组件名] --> [组件名] @enduml` | 2.1, 2.2 |
| class | `@startuml class ClassName { +method() } @enduml` | 3.1, 3.3 |
| sequence | `@startuml Alice -> Bob: message @enduml` | 6.1 |
| usecase | `@startuml Actor --> (UseCase) @enduml` | 1.1 |
| state | `@startuml [*] --> State1 @enduml` | 3.1 |
| activity | `@startuml start -> (action) -> stop @enduml` | 4, 6 |
| deployment | `@startuml node "Server" { [Artifact] } @enduml` | 13.1 |
