# 云见 Skill 与经验查找及使用

## 接入与边界

1. 判断入口：SDD 中以已形成的任务及上下文为输入；其他场景以当前任务为输入，先安装并读取**云见 CLI Skill**。已安装时直接读取使用。
2. 区分云见 CLI Skill（CLI 操作指引）与任务实际需要的业务 / 通用 Skill。不要将本 Skill 当作云见 CLI Skill 的替代品。
3. 在 SDD 中读取可用的云见 CLI 操作指引。所有产品、场景、Skill、经验的查找与获取均通过云见 CLI 完成；以实际安装的 CLI Skill、帮助信息和返回结果确定操作，不编造命令、参数、接口或标识。
4. CLI、操作指引、身份或服务不可用时，明确说明本次未能获取能力，继续原任务；不要改用其他工具绕开 CLI。其他场景安装入口不可用时也按此处理。
5. 不设计新的目录布局、tasks.md 字段、索引文件或版本协议；遵循项目已有约定。下载的内容必须位于当前项目范围。

## 按任务选择路径

由 Agent 根据目标、代码仓和任务上下文自主判断业务相关能力或通用能力；同一任务需要两类能力时分别执行对应路径。

| 能力需求 | 执行路径 |
|---|---|
| 业务相关 | 通过云见 CLI 由代码仓识别产品 → 获取产品场景 → 从场景匹配 Skill → 选择适合任务的 Skill |
| 业务路径未命中 | 无法定位产品 / 场景，或场景内没有合适 Skill 时，通过云见 CLI 分别检索最多 **3 个 Skill 候选**和经验引擎中最多 **3 条经验候选** |
| 通用能力 | 跳过产品和场景链路，直接通过云见 CLI 检索并选择通用 Skill |

- 对业务未命中的两类候选综合判断相关性、适用条件和任务约束，选择 Skill、经验或两者组合；不要求全选或各选一项。
- 不足 3 个时按实际数量处理，不为凑数扩大候选。结果不合适时不强行选用。
- 不将业务未命中的经验检索变成所有任务必做的经验检索。
- 一侧检索失败时仍可判断另一侧已返回的候选，说明缺失情况；服务错误不等同于确认没有结果。
- 场景已匹配合适 Skill 时直接选用；通用路径不自动追加业务兜底的经验检索。

## 获取、关联与使用

1. 将选中的 Skill 和经验通过云见 CLI 下载到项目级目录，确认内容实际可读，再用于对应任务。下载失败的内容不得标记为可用；可使用其余成功获取的内容。
2. **SDD**：同步修改该任务所在的 `tasks.md`，将实际选用内容与对应任务关联，提供后续执行所需的本地上下文定位。使用现有任务描述约定，保留任务编号、checkbox、设计锚点及测试策略。没有选用结果或获取失败时如实说明，不写入虚构的成功关联。
3. **其他场景**：直接用于当前任务，**不修改 tasks.md**，即使项目中存在该文件也不例外。
4. `tasks.md` 是 SDD 任务及其能力关联的唯一数据源；本地下载文件只承载能力内容，不另建 skill-index、映射 JSON 或其他任务能力索引。
5. 执行已有 SDD 任务时先从 `tasks.md` 读取关联，使用已下载且仍适用的内容。缺少关联、内容丢失或任务需求变化时，再按上述路径查找 / 获取，并同步更新原任务关联。
6. 多仓场景以任务所属代码仓定位产品，内容落到对应仓的项目级目录，关联写入该仓的 `tasks.md`；不要在根项目另建汇总索引。各仓执行者必须自行读取关联与本地内容。
7. 不因广场正式 Skill 更新而自动覆盖已有项目本地内容；需要更新时走项目后续获取或更新流程，再同步实际关联。清理临时文件时保留任务仍引用的 Skill 和经验。

## 汇报与后续衔接

简要报告能力判断、查找路径、实际选用及获取结果；SDD 补充说明任务关联同步结果。查找或下载失败不阻断原任务，未成功同步关联时不得宣称同步完成。

查找使用可以独立结束，不要求每次使用都评测或进化。评测与建议生成是外部前置能力；仅在拿到对应 Skill 的改进建议后，才转入 [yunjian-skill-evolve](../yunjian-skill-evolve/SKILL.md)。经验参与任务使用，本方案进化审核对象仅为 Skill。
