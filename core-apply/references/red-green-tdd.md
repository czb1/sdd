# 测试先行（tdd 模式）执行指令

> 本文件为 tdd 模式下的测试先行执行指令，是 code-generation-procedure.md 10.5.2 / multi-codegen-template.md step c 中"执行代码生成（测试先行）"的实现细节。仅在 tasks.md 头部 `测试策略: tdd` 时被 Read；test-after 不读取。

## 测试工程初始化（进入红-绿循环前执行一次）

读取 tasks.md 第一个任务的"测试文件路径"和"测试命令"字段，检查测试工程是否就绪：
- 测试目录存在（如 tests/）
- 构建文件存在（如 package.json / CMakeLists.txt / pom.xml，按编程语言判断）
- 测试命令可运行（不报 "no such file" / "command not found"）

**任一缺失则先初始化**：按 tasks.md 各任务的"测试文件路径"和"测试命令"字段推断测试框架与目录结构，创建测试目录、构建文件、确保测试命令可执行（空测试文件可运行即可）。已全部就绪则跳过本步。

## 红-绿循环（每个代码生成任务）

1. 读取任务目标、涉及文件和特有字段（覆盖用例/测试文件路径/测试命令）
2. 读取关联的 delta_spec/delta_design 章节（锚点已由 10.2/10.3 解析）
3. **编写失败的测试（红灯）**：按任务"覆盖用例"字段，参考 delta_test_design.md 对应 TC，手写测试到任务指定的测试文件路径（项目测试工程）
4. **运行测试确认失败（确认红灯）**：运行任务指定的测试命令，确认测试因功能缺失失败（编译失败或断言失败都是预期的红，禁止跳过）
5. **实现最少代码（绿灯）**：按 10.4 原则自检结果与实现约束完成最小实现
6. **运行测试确认通过（确认绿灯）**：重跑测试命令，确认全部通过
7. **编译检查**
8. 标记任务完成: `- [ ]` → `- [x]`

## 红-绿验证纪律

- 没有看到测试失败，不允许写实现代码
- 测试通过但没确认过失败 = 无效验证（可能测试的是已有行为）
- 断言失败时：先裁决"实现错还是测试断言错"——依据 delta_test_design.md 预期结果，实现错→回改实现；测试断言错→修测试。禁止为让测试通过而篡改测试意图（删调用/弱化断言/改期望值适配实现）

## 细则来源

- 进入红-绿循环前，加载 test-driven-development 技能（`skills/test-driven-development/SKILL.md`，含 `@testing-anti-patterns.md`），按其中的红-绿细则执行：验证红灯必须执行、验证绿灯必须执行、测试反模式检查（禁止测试 mock 行为/在生产类加仅测试方法等）

## 前置条件

测试工程已初始化（见上方"测试工程初始化"步骤）。
