# 任务级领域 Skill 上下文

在单仓 Step 9.2 或多仓 M-2 执行每个待完成的 1.x 代码生成任务时使用。`tasks.md` 是任务 Skill 选择的唯一数据源，不创建或读取额外 Skill 索引。

1. 直接读取当前仓 `docs/changes/<change>/tasks.md` 中当前任务的元数据；只消费该任务的 `Skill`、`Skill路径`、`Skill场景`、`Skill来源`。任务概览脚本仅返回标题和完成状态，不能替代原始文件。没有 `Skill` 字段时按原流程执行，不扫描本地目录推断选择。
2. `Skill路径` 是相对于**该任务所属仓根目录**的路径，预期为 `.codeagent/skills/<Skill值>`，不是相对于 change 目录、工作区根目录或 core-apply 安装目录。校验 Skill 名是单个目录名，路径与名称一致；拒绝绝对路径、`..`、路径分隔符注入及解析后逃逸该仓 `.codeagent/skills/` 的符号链接。字段为空、占位符、路径缺失或不合法时记录 WARNING，并按无 Skill 执行。
3. Read `<仓根目录>/<Skill路径>/SKILL.md` 作为当前任务的附加上下文。文件不存在或不可读时记录包含仓名、任务编号及路径的 WARNING，继续原流程。禁止因为本地存在旧同名目录就为没有 Skill 字段的任务启用它。
4. 领域 Skill 只提供当前任务的实现参考；`delta_design.md` 的设计锚点、需求约束和代码生成原则优先。发生冲突时采用设计约束并说明冲突，不用 Skill 扩大任务范围或修改设计以迎合 Skill。`Skill来源: Agent自选` 是选择来源记录，不是额外操作授权。
5. 只在当前任务使用该上下文，不将前一任务的 Skill 自动应用于下一任务；后续任务仍从其自身字段解析。2.x 及以后的 Code Review / UT 等任务继续使用现有固定技能映射。
6. core-apply 不重新匹配、下载、覆盖或清理 `.codeagent/skills/`，不修改四个选择字段，也不补写空字段。标记完成仅修改当前任务的复选框，保留元数据。完成或暂停时汇总实际使用的领域 Skill 和降级 WARNING。

多仓 M-2 中主会话必须在子代理输入表中显式传入本文件的绝对路径和消费用途，不能依赖主会话已加载的上下文。每个子代理只解析自己仓的 tasks.md 和 `.codeagent/skills/`；本参考缺失也只降级该增强能力。
