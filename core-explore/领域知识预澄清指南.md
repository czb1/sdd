# 领域知识预澄清指南

本指南用于帮助 Agent 识别**知识性问题**，并仅针对知识性问题向云见知识助手提问。

* **知识性问题**：业务概念、领域知识、业务规则或背景不明确，需要外部知识补充。
* **流程问题**：业务含义已明确，但涉及系统实现、流程流转、异常处理或研发协作，应基于代码、设计文档和 SDD 规范分析，**不要向知识助手提问**。

> **只为澄清“是什么”提问，不为解决“怎么做”提问。**

## 一、识别知识性问题

当 Agent 无法回答以下问题时，可判断为知识性问题：

* 这个业务概念或专有名词是什么？
* 某个指标、字段或对象的业务含义是什么？
* 某项业务规则如何定义？
* 某个业务场景有哪些类型或范围？
* 某个网元、角色或业务对象在领域中的职责是什么？

**识别特征：**

* 包含用户自定义的专有名词或缩写；
* 需求只描述“要做什么”，但缺乏业务背景或动机；
* 涉及特定行业的业务规则、合规要求或业务限制。

**典型问题：**

> 用户质差结果具体指什么？

> NEF 网元在流程中的位置？

> 流过滤器有哪些属性和方法？

> 归属 PLMN 和拜访 PLMN 在国际漫游场景下分别表示什么？

## 二、识别并避免流程类问题

当**业务概念已经明确**，但问题涉及以下内容时，应判断为流程问题：

* **状态**：状态如何切换、切换条件是什么；
* **时序**：什么时候调用、什么时候同步；
* **分支**：多条处理路径如何选择；
* **异常**：超时、失败、重试如何处理；
* **边界**：长度、空值、次数等特殊情况如何处理；
* **数据流**：数据从哪里来、传给谁；
* **实现**：已有能力还是需要新增；
* **冲突**：需求与当前代码或设计不一致时如何处理；
* **决策**：存在多个合理方案，需要用户拍板。

**典型问题：**

> 当异步任务执行失败时，系统流程是直接抛出异常并通知用户，还是自动进入 3 次重试队列？

> VIP 用户保障 API，是 CMHK 用户已有的 API 还是需要重新开发？如果已有，实现位置在哪？

> 需求说选择 TAI 时下拉框呈现 4G 跟踪区信息，但当前 UPF 指标使用的是 5G TAI 维度，是否需要改为 4G TAI 维度？

> 漫游场景维度的交互方式应该是什么？是下拉选择框还是其他方式？

> **判断流程问题时，重点关注“状态、时序、分支、异常、边界、数据流和实现决策”，不要仅根据“流程”“API”等关键词判断。**

## 三、提问规则

仅在确认属于知识性问题后，向知识助手提问：

### 1. 一次只问一个知识点

**正例：**

> 归属 PLMN 和拜访 PLMN 在国际漫游场景下的含义是什么？

**反例：**

> VoLTE 融合 UPF 语音指标中，注册成功率为什么不区分主被叫？漫游场景维度的枚举值有哪些？归属 PLMN 和拜访 PLMN 在国际漫游场景下的含义是什么？

### 2. 多问“是什么”，少问“为什么”

**正例：**

> 漫游场景维度的枚举值有哪些？

> PES 与 SGM 之间共享配额数据的同步机制是怎样的？

**反例：**

> VoLTE 融合 UPF 语音指标中，注册成功率指标为什么不区分主被叫？

### 3. 问具体的问题，保留必要上下文

**正例：**

> 归属 PLMN 和拜访 PLMN 在国际漫游场景下的含义是什么？

**反例：**

> XXX 的背景是什么？

### 4. 不要预设答案

不要将 Agent 的猜测直接写进问题，应先获取领域事实，再基于事实进行后续分析。

> **一个问题 → 一个知识点 → 必要上下文 → 不预设答案**
